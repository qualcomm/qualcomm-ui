# {frontmatter.title}

Set up React VS Code for an extension webview that uses the editor's fonts and colors. Build the workspace library, then use embedded documentation demos to preview its styles.

The package is under development and has no released consumer version yet. The React package exports a host stylesheet and CSS typography utilities. Import token metadata and opacity bindings directly from `@qualcomm-ui/vscode-core`. React component APIs are not available yet.

## Prerequisites

Use a checkout of the NextGen `qualcomm-ui` repository, its configured pnpm version, and Node.js 22.12 or newer for the build tools. The library requires React and React DOM 19 or newer. A consuming extension defines its supported VS Code version.

## Install and build the workspace library

Run these commands from the repository root:

```shell
pnpm install
pnpm vscode-core build
pnpm react-vscode build
```

The build emits ESM entrypoints, TypeScript declarations, and the public stylesheets. In a workspace consumer, declare `@qualcomm-ui/react-vscode`, React, React DOM, and the library's shared-core peer packages. pnpm resolves the library through the workspace.

## Import the host stylesheet

Import the public stylesheet from your React entry point:

```tsx
import "@qualcomm-ui/react-vscode/styles.css"
```

Add `qui-vscode` to the webview body or the container wrapping your application:

```html
<body class="qui-vscode">
  <div id="root"></div>
</body>
```

The stylesheet reads `--vscode-font-family`, `--vscode-font-size`, `--vscode-font-weight`, and `--vscode-foreground`. VS Code supplies these values inside the webview. Theme colors update through the host variables.

QDS font downloads, brand CSS, QDS theme providers, and Tailwind are not prerequisites for an extension using this package. Add icon assets and the corresponding content security policy permissions when your interface uses them.

## Preview and verify

Use the embedded [Browser Preview](/setup/browser-preview) to try host styling and switch between simulated light, dark, and high-contrast themes. Component previews run inside the documentation site; no separate preview server is required.

Follow [Webview Setup](/setup/webview) to integrate the library into your extension and verify real host fonts, themes, asset loading, and lifecycle behavior. Embedded demos do not exercise extension messaging or a production webview content security policy.

## Develop the documentation

The docs demonstrate the optional Tailwind adapter. Build its generated styles before starting the site:

```shell
pnpm tailwind-plugin generate-css:vscode
pnpm tailwind-plugin build:css
pnpm react-vscode-docs dev
```

The documentation site uses port 3400.

The documentation shell uses the shared QUI Docs layout and QDS styling. VS Code component previews use simulated host variables within their preview containers. A real extension receives its font and color variables from the host.

## Choose appearance and behavior

Reuse design-agnostic `core` and `react-core` behavior. Use the VS Code package for host appearance and the QDS React package for QDS brand appearance.

Read [host theming](/theming/overview) before adding styles. [Typography](/components/typography) documents the first implemented styles.
