# {frontmatter.title}

Integrate React VS Code into your extension's browser bundle, then verify its fonts, colors, and interactions in an Extension Development Host. The extension owns VS Code APIs and webview lifecycle; the library supplies React components and presentation.

## Build the browser application

Complete [Installation](/installation). Import the library stylesheet from your browser entry point:

```tsx
import "@qualcomm-ui/react-vscode/styles.css"
```

Apply `qui-vscode` to the application container or webview body. Bundle React, React DOM, the library, and required shared-core dependencies with your extension's browser build. Use relative asset paths when configuring Vite or another bundler for local webview files.

Keep the runtimes separate:

| Runtime | Responsibility |
| --- | --- |
| Extension host | Register commands, create panels, call VS Code APIs, validate messages, and manage lifecycle |
| React webview | Mount React, import library styles, render components, and request host operations through messages |

Browser code must not import `vscode`, Node.js modules, or extension-only modules. The component library does not create panels or provide an application messaging protocol.

## Load local webview assets

In your extension, create the panel with `window.createWebviewPanel` and enable scripts for the React application. Restrict `localResourceRoots` to the directories containing your built assets.

Convert JavaScript, stylesheet, image, and font file URIs with `webview.asWebviewUri` before including them in the HTML shell. Keep asset filenames and any lazy-loaded chunks consistent with the browser build output. Filesystem paths and development-server URLs are not production asset URLs.

Define a content security policy for the resources your application uses. Start with `default-src 'none'`, allow local styles through `webview.cspSource`, and use a generated nonce for permitted scripts. Allow image and font sources only when those resources are needed. Keep user content out of the HTML shell and render it as React text unless you have an explicit sanitization contract.

Read Microsoft's [Webview API guide](https://code.visualstudio.com/api/extension-guides/webview) for panel creation, local resource loading, and content security policy examples.

## Connect extension operations

Acquire `acquireVsCodeApi()` once in your browser integration module and keep the returned object private to that module. Register message listeners before sending readiness messages so the initial response is not lost.

Send requests with the webview API's `postMessage` method. Receive requests in the extension through `webview.onDidReceiveMessage`, and send responses with `webview.postMessage`. Define and validate request and response shapes at runtime; TypeScript types alone do not validate messages. Applications decide their command names, request IDs, error responses, and cancellation behavior.

Use `getState()` and `setState()` for JSON-serializable webview state. Restoring panels after VS Code restarts requires an extension-owned `WebviewPanelSerializer`. The component library does not manage panel persistence.

## Verify in your extension

Build your extension and launch its existing F5 configuration. Open the panel from the Extension Development Host and verify:

1. The React application mounts and its local JavaScript and CSS load without content security policy errors.
2. The `qui-vscode` container uses host fonts and colors. Switch between light, dark, and high-contrast themes while the panel is open.
3. Keyboard interactions, accessible names, focus handling, and focus restoration work for the components in use.
4. Requests and responses pass your runtime validation, and failed operations produce useful application feedback.
5. Webview state behaves correctly when the panel is hidden, recreated, or closed, according to your extension's lifecycle contract.

Use webview developer tools to inspect blocked assets or runtime errors. If the library stylesheet cannot be resolved in the workspace, run `pnpm react-vscode build`. If theme colors do not apply, check the stylesheet import and `qui-vscode` container, and remove browser preview fixtures from the real webview.

The [Browser Preview](/setup/browser-preview) demonstrates rendering and saved theme snapshots inside this documentation site. It does not exercise real extension messaging, production asset loading, or panel lifecycle.

Read Microsoft's [extension bundling guide](https://code.visualstudio.com/api/working-with-extensions/bundling-extension) and [VS Code API reference](https://code.visualstudio.com/api/references/vscode-api) for the wider integration contracts.
