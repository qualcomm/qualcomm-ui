## Defining Filters

::: terms
defineFilters, filter definitions, filter types
:::

Filters are declared up front with `defineFilters`. Each key becomes the filter's id. Each value is a filter definition.

```ts
import {defineFilters, listFilter} from "@qualcomm-ui/core/filters"
import {ListCollection} from "@qualcomm-ui/utils/collection"

export const filters = defineFilters({
  architecture: listFilter({
    collection: new ListCollection({items: ["arm64", "x86-64"]}),
    label: "Architecture",
  }),
  platform: listFilter({
    collection: new ListCollection({items: ["Linux", "macOS", "Windows"]}),
    label: "Platform",
  }),
  status: listFilter({
    collection: new ListCollection({items: ["Failed", "Passed", "Queued"]}),
    label: "Status",
  }),
})
```

The utility sets the filter's label, collection, and value type. The control renders it inside `q-filter-panel-filter`. The controls are documented on the [Filter Controls](./filter-controls+/_filter-controls.mdx) page.

Templates only read component members, so assign the definitions to a field, such as `readonly filters = filters`.

### Manual & Controlled State

In `manual` mode, [value](#value) is the applied (saved) selection and [draftValueChanged](#draftValueChanged) emits the panel's staged selection. They only differ in manual mode, until the draft is applied.

Setting `value` from outside the panel replaces the draft, including any unapplied changes.

### Labels

::: terms
label, heading, custom label, filterContext
:::

The definition's `label` is the filter's name everywhere: the section heading, the control's accessible name, and [getFilterLabel](#getFilterLabel).

To change the text of a single section heading, set the `label` input on `q-filter-panel-filter`. For markup, or to build on the definition's label, project a `q-filter-panel-filter-label` element. `*filterContext` exposes the filter's state, including the definition's `label`. The rendered heading also names the control, but summaries keep the definition's label.

<QdsDemo name="FilterPanelLabelsDemo" />

### Loading Options

::: terms
async options, loading, error, retry, ListCollection, TreeCollection, getFilterCollection, injectQuery
:::

To load a filter's options from an API, leave `collection` off its definition. Use the [getFilterCollection](#getFilterCollection) input to provide the collection. Load the data elsewhere, like with a query library, and return `undefined` until it arrives. A filter without a collection shows no options.

The resolver can read signals, such as a query's data. The filter re-resolves its collection when they change.

The panel doesn't show loading or error states. Render them yourself. This example shows a progress ring next to the filter label, through a projected `q-filter-panel-filter-label`, while the request is pending. If the request fails, an error message with a Retry button replaces the control.

<QdsDemo name="FilterPanelLoadingOptionsDemo" />

### Restoring a Selection

::: terms

:::

A selection restored from a URL like `/builds?owner=u2` may only contain value ids. Anything that shows the selection outside the panel, like these chips, should wait for the collection data before calling `getValueItems`.

### Filter Counts

::: terms
faceting, facets, result counts, FacetIndex, getFacetFilterSetProps
:::

To show the number of results next to each filter option, provide the counts with the [getFilterOptionCounts](#getFilterOptionCounts) input. Unselected checkbox and radio options with a count of 0 are disabled.

```angular-ts
readonly getFilterOptionCounts = (id: FilterId<typeof filters>) =>
  this.response()?.facets?.[id]
```

```angular-html
<div
  q-filter-panel-root
  [filters]="filters"
  [getFilterOptionCounts]="getFilterOptionCounts"
></div>
```

When you have access to the entire dataset up front, you can use our `FacetIndex` utility to compute option counts that adjust based on filter selection. Bind both functions returned by `getFacetFilterSetProps` to the root.

<QdsDemo name="FilterPanelFilterCountsDemo" />

In manual mode, counts follow the draft, so they update before the user applies.

### Dynamic Filter Counts

::: terms
fetched data, TanStack Query, injectQuery, loading
:::

A [FacetIndex](facet-index.mdx) can only count the items you give it. When working with an external data source, we recommend sending a separate unfiltered request once at the start of your search experience. This approach requires the unfiltered query to return every available option. **Every option then stays in its list, even as the filters narrow the results.**

> [!note]
> When the full dataset is too large to fetch, compute only the counts on the server and send those instead. If you're using a proper search index like Open/Elastic Search, this is typically accomplished with [Term Aggregations](https://www.elastic.co/search-labs/tutorials/search-tutorial/full-text-search/facets).

This example uses [TanStack Query](https://tanstack.com/query) through `injectQuery`, with a mock endpoint in place of a search API.

<QdsDemo name="FilterPanelDynamicFilterCountsDemo" />

Neither filter has a collection, so each lists the values of its field from the index. Until the index loads, the filters have no options, so each shows a progress ring next to its label.

### Hoisted State

::: terms
useFilterSet, q-filter-panel-root-provider, chips, active filters
:::

`q-filter-panel-root` handles the filter set state internally. Use `useFilterSet` with `q-filter-panel-root-provider` to own that state in your component, where code outside the panel can read and change it. `useFilterSet` returns a signal, so pass `filterSet()` to the provider's `[value]`.

<QdsDemo name="FilterPanelHoistedStateDemo" />

To read the panel's filter set from the template without hoisting it, use the root's `filterPanelRoot` export:

```angular-html
<div #panel="filterPanelRoot" q-filter-panel-root [filters]="filters">
  ...
</div>
<span>{{ panel.filterSet().valueCount }} filters applied</span>
```

The state lives in the component that calls `useFilterSet`. This way, the panel can unmount without losing the selection, like in a drawer:

<QdsDemo name="FilterPanelDrawerDemo" />

### Filters in Child Components

::: terms
useFilterSetContext, nested components, typed definitions
:::

In a nested component, use `useFilterSetContext` to access the closest provider's filter state. For type safety, pass the type of your definitions:

```angular-ts
// build-filters.ts
export const filters = defineFilters({...})
export type BuildFilters = typeof filters

// status-filter.component.ts
import type {BuildFilters} from "./build-filters"

@Component({
  imports: [FilterPanelModule, FiltersModule],
  selector: "status-filter",
  template: `
    <div q-filter-panel-filter [filter]="filterSet().filters.status">
      <q-checkbox-group-filter />
    </div>
  `,
})
export class StatusFilter {
  protected readonly filterSet = useFilterSetContext<BuildFilters>()
}
```

`useFilterSetContext` returns a signal. Call it in an injection context, such as a field initializer.

The type isn't checked against the panel's definitions. In development, a filter warns when its definition is missing from the panel's `filters`.

### Custom Filters

::: terms
custom control, useFilter
:::

Declare a filter with your own value type using `customFilter`. `isEmptyValue` tells the panel when to drop the filter from the value, and `getValueItems` describes the value in active filter tags.

```ts
const filters = defineFilters({
  attachments: customFilter<boolean>({
    getValueItems: () => [{label: "Has attachments", value: "true"}],
    isEmptyValue: (value) => !value,
    label: "Attachments",
  }),
})
```

Render your custom control inside `q-filter-panel-filter`. `q-filter-panel-filter` provides the filter's state to its content. Use `useFilter` to read it. The returned signal holds `undefined` when the filter has no definition, so guard the control's template with `@if (filter(); as filter)`.

### useFilterSet

Accepts the same state props as [q-filter-panel-root](#q-filter-panel-root), with `onValueChange` and `onDraftValueChange` callbacks in place of its outputs. Returns a signal of the filter set API. Call it in an injection context, such as a field initializer. Pass a signal of the props to update them after creation.

<TypeDocProps name="FilterSetApi" partial />

### useFilter

Returns a signal of the state of the enclosing `q-filter-panel-filter` or `q-filter-provider`. The signal holds `undefined` when the filter has no definition. Call it in an injection context, such as a field initializer.

<TypeDocProps name="FilterState" partial />

### filterContext

A structural directive that renders its template with the same state as `useFilter`. It renders nothing when the filter has no definition.

```angular-html
<span *filterContext="let filter" q-filter-panel-filter-label>
  {{ filter.label }} ({{ filter.count }})
</span>
```
