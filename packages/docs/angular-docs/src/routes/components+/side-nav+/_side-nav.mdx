## Overview

The side nav is an extension of our [tree](/components/tree) component.

- The Side Navigation relies on the `TreeCollection` class to manage its items. Refer to the [API](./#tree-collection) below for details.
- Like with the tree, Side Navigations are composed of nodes, which are objects that describe the navigation data. There are two types of nodes:
  - A `branch` node has children.
  - A `leaf` node does not have any children.
- Each node has a `value` (unique identifier used for expansion) and a `text` (display text).

**Default object shape:**

- `value` (required): unique identifier for expansion/selection
- `text` (required): display text
- `nodes` (optional): child nodes for branches
- `disabled` (optional): prevents interaction when `true`

These keys can be customized via the `TreeCollection` [constructor](./#constructor).

## Examples

### Node Shorthand

We expose the `<q-side-nav-nodes>` shorthand for rendering nested nodes. Use the following directives to customize the tree nodes:

```angular-html tabs="nodes" label="branch"
<ng-template
  let-branch
  q-side-nav-branch-template
  [rootNode]="collection.rootNode"
>
  <div q-side-nav-branch-node>
    <!-- ... -->
  </div>
</ng-template>
```

```angular-html tabs="nodes" label="leaf"
<ng-template let-leaf q-side-nav-leaf-template [rootNode]="collection.rootNode">
  <div q-side-nav-leaf-node>
    <!-- ... -->
  </div>
</ng-template>
```

Note that `<q-side-nav-nodes>` automatically renders child nodes for branches, so you only have to customize the content of the node itself.

<QdsDemo name="SideNavNodeShorthandDemo" />

> [!tip/Node Types]
> Pass the `rootNode` input to the template directives to enable TypeScript type inference. This allows `branch.node` and `leaf.node` to have your custom node type instead of the generic `TreeNode` type.

### Grouping

::: terms
section divider, categorize items, navigation sections
:::

Group nodes using the collection's [groupChildren](./#groupChildren) method. This should be called on the top-level node of your SideNav. Nested groups are not supported.

<QdsDemo name="SideNavGroupsDemo" />

### Sizes

::: terms
compact, density, small, medium
:::

Use the [size](./#size) input to control item padding, height, spacing, font size, and icon size. The available sizes are `sm` and `md` (default).

<QdsDemo name="SideNavSizeDemo" />

### Default Expanded

::: terms
initially open, pre-expanded
:::

Expand nodes by default using the [defaultExpandedValue](./#defaultExpandedValue) input. Or use [expandedValue](./#expandedValue) and [expandedValueChanged](./#expandedValueChanged) to control the expansion manually. These inputs follow our [controlled state](/patterns/controlled-state) pattern.

<QdsDemo name="SideNavDefaultExpandedDemo" />

### Disabled Nodes

::: terms
inactive
unavailable
:::

You can disable nodes by setting the `disabled` property on the node object.

<QdsDemo name="SideNavDisabledNodeDemo" />

### Collapsed

::: terms
minimize, icon-only, compact, hamburger, drawer menu
:::

Side Nav can be collapsed to render only the top-level icons.

The open state of the panel can be controlled using the [open](./#open), [openChanged](./#openChanged) and [defaultOpen](./#defaultOpen) inputs. These inputs follow our [controlled state](/patterns/controlled-state) pattern.

<QdsDemo name="SideNavCollapsedDemo" />

### Filtering

fuzzy search

Here's an example that filters the items using `matchSorter`.

### Links

::: terms
routerLink, angular router, router integration
:::

Side Nav nodes can be links. Apply the `q-side-nav-leaf-node` directive to an anchor element with `routerLink` to create navigable links.

<QdsDemo name="SideNavLinksDemo" />

### Surface

::: terms
dark background, light background
:::

Use the `surface` input to change the background color of the Side Nav.

<QdsDemo name="SideNavSurfaceDemo" />

### Tooltips

::: terms
hover hints, icon labels
:::

Consider wrapping collapsed nodes with the [Tooltip](/components/tooltip) component to provide context about each item. This is also useful for describing disabled nodes.
