# {frontmatter.title}

This guide is for contributors to the qualcomm-ui component library. The library is a cross-framework design system built on a headless state machine architecture, with implementations for React and Angular.

## Architecture at a Glance

The library is organized into four layers:

- **Layer 1: Headless Core** (`core`, `dom`, `utils`): Framework-agnostic state machines, DOM abstractions, and shared utilities that define component behavior without any UI.
- **Layer 2: Framework Adapters** (`react-core`, `angular-core`): Hooks, components, and directives that wrap the headless machines for each framework.
- **Layer 3: Design System** (`qds-core`): CSS classes, design tokens, and visual APIs that implement the QDS specification.
- **Layer 4: Styled Components** (`react`, `angular`): Consumer-facing components that merge all layers into a single import.

The [Architecture](/contribution-guidelines/architecture) page covers each layer in detail.

| Package | Description |
| :-- | :-- |
| `core` | Headless state machines and component APIs |
| `dom` | DOM abstractions (focus, positioning, queries) |
| `qds-core` | Design tokens, CSS classes, QDS styling APIs |
| `utils` | Zero-dependency shared utilities |
| `angular` | Styled Angular components (QDS) |
| `angular-core` | Angular directives and services wrapping core |
| `react` | Styled React components (QDS) |
| `react-core` | React hooks and context wrapping core |
| `react-mdx` | Shared MDX components for docs |
| `eslint-config-*` | Shared ESLint configurations |
| `angular-csr` | Angular CSR debug app |
| `angular-ssr` | Angular SSR debug app |
| `react-ssr` | React SSR debug app |
| `angular-docs` | Angular documentation site |
| `react-docs` | React documentation site |

> [!note]
> React contributors cannot skip Angular sections, and vice versa. However, you can start with one framework's implementation and learn the other afterward. The shared layers (`core`, `dom`, `qds-core`, `utils`) are required knowledge for both.
