## Overview

The filter panel renders filter controls and tracks the user's selection. You use that selection to filter your data.

## Defining Filters

::: terms
defineFilters, filter definitions, filter types
:::

Filters are declared up front with `defineFilters`. Each key becomes the filter's id. Each value is a filter definition.

```tsx
import {
  checkboxFilter,
  defineFilters,
  rangeFilter,
  textFilter,
} from "@qualcomm-ui/core/filters"

export const filters = defineFilters({
  buildPath: textFilter({label: "Build path"}),
  duration: rangeFilter({label: "Duration", max: 120, min: 0}),
  status: checkboxFilter({
    label: "Status",
    options: ["Failed", "Passed", "Queued"],
  }),
})
```

These definitions match our [filter controls](/components/filters): `checkboxFilter` defines a filter for `<CheckboxFilter>`, `textFilter` for `<TextFilter>`, and so on. The utility sets the filter's label, options, and value type. The control renders it. The controls are documented on the [Filters](/components/filters) page.

```tsx
import {FilterPanel} from "@qualcomm-ui/react/filter-panel"
import {CheckboxFilter} from "@qualcomm-ui/react/filters"

function PanelDemo() {
  return (
    <FilterPanel.Root filters={filters}>
      <CheckboxFilter filter={filters.status} />
    </FilterPanel.Root>
  )
}
```

## Examples

### Basic

::: terms
clear all, count, header
:::

By default, every change is committed as it happens and calls [onValueChange](#onValueChange). `FilterPanel.Count` shows the number of selected values, and `FilterPanel.ClearButton` clears every filter.

### Controlled State

::: terms
controlled, value, onValueChange
:::

Set the initial selection using the [defaultValue](#defaultValue) prop, or use [value](#value) and [onValueChange](#onValueChange) to control it manually. These props follow our [controlled state](/patterns/controlled-state) pattern.

The second argument to `onValueChange` contains the labels of the options the user selected, keyed by filter id and option value. This is useful for options that are loaded at runtime, where the label isn't known ahead of time.

### Manual & Controlled State

In `manual` mode, `value` is the applied (saved) selection and `draftValue` refers to the panel's staged changes.

Setting `value` from outside the panel replaces the draft, including any unapplied changes.

### Labels

::: terms
label, heading, custom label
:::

The definition's `label` is the filter's name everywhere: the section heading, the control's accessible name, and value summaries like [getValueLabels](#getValueLabels).

To change how a single section heading renders, pass `label` to the control. It accepts a `ReactNode`, or a function that receives the definition's label. The rendered heading also names the control, but summaries keep the definition's label.

### Options

::: terms
async options, dynamic options, loaded options
:::

Static options belong on the definition. Options that are loaded at runtime are passed to the control, and take precedence over the definition's options.

Options are strings or `{label, value}` objects. A selected value that isn't in the current options stays visible, so the user can always deselect it.

<Demo
  name="FilterPanelOptionsDemo"
  component={demos.FilterPanelOptionsDemo}
/>

A selection restored from storage has no option labels until its options load. To label it in the meantime, supply [getFilterOptionLabel](#getFilterOptionLabel) on the panel, or `getOptionLabel` on the definition.

### Facet Counts

::: terms
faceting, facets, result counts, FacetFilter, getFacetFilterPanelProps
:::

[getFilterOptionCounts](#getFilterOptionCounts) shows how many results each option would produce. It receives a filter id and returns the counts keyed by option value, as a `Map` or a plain object. Unselected options with a count of 0 are disabled. Return `undefined` to show no counts for a filter.

For data in memory, index it with `FacetFilter` from `@qualcomm-ui/utils/facet-filter`, and pass the props from `getFacetFilterPanelProps` to the panel. Filter ids match the facet filter's field names. Each option counts the results it would produce given the selections in the other filters, so options in the same filter don't zero each other out.

`FacetFilter` matches `string[]` values only. Apply text, range, and date filters in `getCandidateIds`, which returns the ids of the items that pass them.

<Demo
  name="FilterPanelFacetsDemo"
  component={demos.FilterPanelFacetsDemo}
/>

Counts from a server can be returned as they arrive.

```tsx
<FilterPanel.Root
  filters={filters}
  getFilterOptionCounts={(id) => response.facets[id]}
>
```

The second argument to `getFilterOptionCounts` is the selection the controls display. In manual mode, that's the draft, so counts update before the user applies. To fetch counts for the draft from a server, create the panel with `useFilterPanel` and request them when [draftValue](#draftValue) changes.

> [!note]
> `getTableFilterPanelProps` supplies counts from the table's faceted values. Enable faceting with the table's `getFacetedRowModel` and `getFacetedUniqueValues` options.

### Hoisted State

::: terms
useFilterPanel, RootProvider, chips, active filters
:::

Create the panel's state with `useFilterPanel` and pass it to `FilterPanel.RootProvider` when you need it outside the panel, like rendering active filters as tags. The state outlives the panel, so the panel can be unmounted (in a closed drawer, for example) without losing the selection.

<Demo
  name="FilterPanelHoistedStateDemo"
  component={demos.FilterPanelHoistedStateDemo}
/>

The API exposes two selections. [value](#value) is the committed selection, and [draftValue](#draftValue) is what the controls currently show. They only differ in manual mode, until the draft is applied. [valueCount](#valueCount) and [draftValueCount](#draftValueCount) count each one, so a "Filters (3)" button outside a closed drawer can show what's applied.

> [!note]
> `clearFilter` follows the apply mode. In manual mode, it clears the filter in the draft, and the change still has to be applied.

### Custom Filters

::: terms
custom control, useFilterPanelFilter
:::

Declare a filter with your own value type using `customFilter`, then render it with the `FilterPanel.Filter` parts. Inside the filter, `useFilterPanelFilter` returns its value and a setter.

```tsx
const filters = defineFilters({
  attachments: customFilter<boolean>({
    getValueLabels: () => ["Has attachments"],
    isEmptyValue: (value) => !value,
    label: "Attachments",
  }),
})
```

`isEmptyValue` tells the panel when to drop the filter from the value, and `getValueLabels` describes the value in summaries.
