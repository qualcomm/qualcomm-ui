## Overview

The filter panel renders filter controls and tracks the user's selection. You use that selection to filter your data.

## Defining Filters

::: terms
defineFilters, filter definitions, filter types
:::

Filters are declared up front with `defineFilters`. Each key becomes the filter's id. Each value is a filter definition.

```tsx
import {
  defineFilters,
  listFilter,
  rangeFilter,
  textFilter,
} from "@qualcomm-ui/core/filters"
import {ListCollection} from "@qualcomm-ui/utils/collection"

export const filters = defineFilters({
  buildPath: textFilter({label: "Build path"}),
  duration: rangeFilter({label: "Duration", max: 120, min: 0}),
  status: listFilter({
    collection: new ListCollection({items: ["Failed", "Passed", "Queued"]}),
    label: "Status",
  }),
})
```

These definitions match our [filter controls](./filters+/_filters.mdx): `listFilter` defines a filter for any list control, like `<CheckboxGroupFilter>`, `treeFilter` for `<CheckboxTreeFilter>`, `textFilter` for `<TextInputFilter>`, and so on. The utility sets the filter's label, collection, and value type. The control renders it inside `FilterPanel.Filter`. The controls are documented on the [Filters](./filters+/_filters.mdx) page.

```tsx
import {FilterPanel} from "@qualcomm-ui/react/filter-panel"
import {CheckboxGroupFilter} from "@qualcomm-ui/react/filters"

function PanelDemo() {
  return (
    <FilterPanel.Root filters={filters}>
      <FilterPanel.Filter filter={filters.status}>
        <CheckboxGroupFilter />
      </FilterPanel.Filter>
    </FilterPanel.Root>
  )
}
```

### Manual & Controlled State

In `manual` mode, [value](#value) is the applied (saved) selection and [draftValue](#draftValue) refers to the panel's staged changes. They only differ in manual mode, until the draft is applied.

Setting `value` from outside the panel replaces the draft, including any unapplied changes.

> [!note]
> `clearFilter` follows the apply mode. In `manual` mode, it clears the filter in the draft, but the change still has to be applied.

### Labels

::: terms
label, heading, custom label
:::

The definition's `label` is the filter's name everywhere: the section heading, the control's accessible name, and value summaries like [getValueLabels](#getValueLabels).

To change how a single section heading renders, pass `label` to `FilterPanel.Filter`. It accepts a `ReactNode`, or a function that receives the definition's label. The rendered heading also names the control, but summaries keep the definition's label.

### Collections

::: terms
ListCollection, TreeCollection, async options, loading, getFilterCollection
:::

List and tree filters select from a collection. A static collection belongs on the definition. A collection that loads at runtime comes from [getFilterCollection](#getFilterCollection), which returns its state: `loading`, `error`, or `success`. The controls show a loading status until it resolves, and an error if it fails. In the panel, the filter's trigger shows a progress ring while the collection refetches, or while the filter is collapsed.

<Demo
  name="FilterPanelOptionsDemo"
  component={demos.FilterPanelOptionsDemo}
/>

`getFilterCollection` is called during render, so load the data elsewhere, such as with a query library, and return its state. List items are strings or `{label, value}` objects unless the collection defines its own accessors. A selected value that isn't in the collection stays visible, so the user can always deselect it.

Labels come from the collection. A selection keeps its labels after a search narrows the collection. Values restored from the URL or storage have no items yet, so the resolver receives them as `values`. Include their items in the returned collection, for example by fetching them by id. Until then, [getValueItems](#getValueItems) reports them as `loading`, so active filter chips can show a placeholder.

### Filter Counts

::: terms
faceting, facets, result counts, FacetFilter, getFacetFilterSetProps
:::

[getFilterOptionCounts](#getFilterOptionCounts) shows the number of results next to each checkbox and radio option. Return counts keyed by option value, or `undefined` to hide counts for a filter. Unselected options with a count of 0 are disabled.

```tsx
<FilterPanel.Root
  filters={filters}
  getFilterOptionCounts={(id) => response.facets[id]}
>
```

For data in memory, index it with [FacetFilter](../../utilities+/facet-filter.mdx) and spread `getFacetFilterSetProps` onto the panel. Its field names must match the filter ids. `FacetFilter` only counts list filters, so apply other filters, like text search, in `getCandidateIds`.

<Demo
  name="FilterPanelFacetsDemo"
  component={demos.FilterPanelFacetsDemo}
/>

In manual mode, counts follow the draft, so they update before the user applies.

> [!note]
> For tables, use `getTableFilterSetProps`. It builds each column's collection from every row, and counts from the table's `getFacetedRowModel` and `getFacetedUniqueValues` options.

### Dynamic Filter Counts

::: terms
fetched data, TanStack Query, useQuery, refetch
:::

When the data comes from a request, build the `FacetFilter` index once the response arrives, and pass its props to the panel. Build the index from a separate unfiltered query. It then counts every value of a field, and values don't drop out of the lists as the filters narrow the results. This example uses [TanStack Query](https://tanstack.com/query), with a mock endpoint in place of a search API.

<Demo
  name="FilterPanelAsyncFacetsDemo"
  component={demos.FilterPanelAsyncFacetsDemo}
/>

A `loading` state with a collection is a refetch. The previous items stay visible, and the filter's trigger shows a progress ring until the new collection arrives.

### Custom Filters

::: terms
custom control, useFilter
:::

Declare a filter with your own value type using `customFilter`, then render your control inside `FilterPanel.Filter`. Inside the filter, `useFilter` returns its value and a setter.

```tsx
const filters = defineFilters({
  attachments: customFilter<boolean>({
    getValueLabels: () => ["Has attachments"],
    isEmptyValue: (value) => !value,
    label: "Attachments",
  }),
})
```

`isEmptyValue` tells the panel when to drop the filter from the value, and `getValueLabels` describes the value in summaries.
