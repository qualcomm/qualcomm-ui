## Overview

Picture a laptop store with two filters, Processor and Operating System. Each option shows how many laptops match it. Select `Snapdragon X Elite` below:

<Demo
  name="FacetIndexOverviewDemo"
  component={demos.FacetIndexOverviewDemo}
/>

The Operating System counts updated to match your selection, so you can see which options have results before you pick one.

This is called faceted search. We provide a `FacetIndex` utility class to enable this type of search in your applications.

## Usage

`FacetIndex` indexes a list of items by the fields you configure. Each call to [filter](#filter) returns the ids of the matching items, and a result count for every value of every field. Each of your items must have a unique string `id`.

```ts
const builds = [
  {id: "1", platform: ["android", "linux"], status: "Failed"},
  {id: "2", platform: ["windows"], status: "Passed"},
  {id: "3", platform: ["linux"], status: "Passed"},
]

const facetIndex = new FacetIndex(builds, {
  fields: {platform: {}, status: {}},
})

const {facets, ids} = facetIndex.filter({
  selections: {platform: ["linux"]},
})
```

```jsonc
// result:
{
  "ids": ["1", "3"],
  "facets": {
    "status": [
      {"docCount": 1, "key": "Failed", "selected": false},
      {"docCount": 1, "key": "Passed", "selected": false}
    ]
  }
}
```

## Counts

::: terms
docCount, buckets, disjunctive faceting, AND, OR
:::

Each field has a bucket for every value in the items. The above example has two buckets for `status`, one for each possible value. A bucket's `docCount` is the number of items with its value, filtered by the other fields.

Selections in different fields combine with AND. In the example above, `linux` is selected, so each `status` count includes only Linux builds:

```jsonc
// facets.status:
[
  {"docCount": 1, "key": "Failed", "selected": false},
  {"docCount": 1, "key": "Passed", "selected": false},
]
```

By default, selections in the same field combine with OR. Selecting `windows` as well adds build 2 instead of removing builds, so the `platform` counts ignore the `linux` selection:

```jsonc
// facets.platform:
[
  {"docCount": 1, "key": "android", "selected": false},
  {"docCount": 2, "key": "linux", "selected": true},
  {"docCount": 1, "key": "windows", "selected": false},
]
```

## Matching All Values

::: terms
match all, AND, tags
:::

Set [match](#match) to `"all"` to require every selected value.

```ts
const devices = [
  {id: "1", features: ["5g", "wifi-7"]},
  {id: "2", features: ["5g"]},
  {id: "3", features: ["bluetooth", "wifi-7"]},
]

const facetIndex = new FacetIndex(devices, {
  fields: {features: {match: "all"}},
})

facetIndex.filter({selections: {features: ["5g"]}})
```

```jsonc
// result:
{
  "ids": ["1", "2"],
  "facets": {
    "features": [
      {"docCount": 2, "key": "5g", "selected": true},
      {"docCount": 0, "key": "bluetooth", "selected": false},
      {"docCount": 1, "key": "wifi-7", "selected": false}
    ]
  }
}
```

Counts follow the same rule. A value's count is the number of results for the current selections plus that value.

## Nested Values

::: terms
path, nested property, dot notation
:::

Set [path](#path) to read a nested property.

```ts
const builds = [
  {id: "1", target: {devices: [{chip: "SM8650"}, {chip: "SM8550"}]}},
  {id: "2", target: {devices: [{chip: "SM8550"}]}},
]

const facetIndex = new FacetIndex(builds, {
  fields: {chip: {path: "target.devices.chip"}},
})

facetIndex.getValues("chip")
// ["SM8550", "SM8650"]
```

Arrays along the path are flattened, so this field holds the chip of every device.

## Narrowing the Candidates

::: terms
text search, candidate ids, search hits
:::

`FacetIndex` only matches field values. To combine it with another filter, like a text search, pass that filter's matches as [ids](#ids). They limit both the results and the counts.

```ts
const hits = builds
  .filter((build) => build.name.includes(query))
  .map((build) => build.id)

const {facets, ids} = facetIndex.filter({
  ids: hits,
  selections: {status: ["Passed"]},
})
```

Results keep the order of `ids`, so ranked results retain their order. Unknown ids are skipped.

## Performance

::: terms
benchmark, speed, memory, large datasets
:::

Large datasets are supported, but we recommend a web worker for datasets exceeding 100k items.

> These results were recorded on an M4 Max with 64GB of RAM. Each item had five fields, including arrays, nested paths, and a field with 1,000 values.

| 100k  | 36.3 ms  | 9.68 MiB   | 102            |
| 300k  | 113 ms   | 32.4 MiB   | 113            |
| 500k  | 180 ms   | 44.6 MiB   | 93.5           |
| 1M    | 360 ms   | 89.1 MiB   | 93.4           |
